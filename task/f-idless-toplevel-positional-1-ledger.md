# F-IDLESS-TOPLEVEL-POSITIONAL-1 — a top-level column of an id-less Parquet file reads by position on the no-mapping route, refuses a type or nesting-kind change, and reads NULL when unmapped

**Outcome in one line.** On the no-mapping route of an id-less Parquet file, a top-level column reads by position (`position + 1`), as Java's fallback stamping does. A column whose file type or nesting kind would change under its positional table field refuses, on projected, predicate and equality-delete key columns. An unmapped top-level column under a partial mapping reads NULL. Round 4 (2026-11-02) reads, on an id-less file's top-level columns, string and binary as one kind, decimals of equal scale at any precision, and an INT96 column over a long as the instant in microseconds; a decimal scale change and a NULL in a required field keep refusing. At `717e2ee5` the 20 pins of `idless_toplevel_positional.rs` and the 13 of `idless_toplevel_positional_2.rs` are green. Round 5 (2026-11-02) makes the filters on the string/binary pair follow Spark's measured matrix (S-33, S-34), makes an overflowing narrowed decimal loud under a filter (S-35) and keeps the raw bytes of a string column read as binary (S-36); at `27287069` the 20, 13 and 8 pins of the three suites are green.

## Why

**The fault.** On the no-mapping route, a top-level file column matched a table column by name and position, and otherwise took `position + 1`. A positional read into another type was cast silently, to NULL or to a wrong value. An unmapped top-level column under a partial mapping was read by position. Java's `ParquetSchemaUtil.addFallbackIds` assigns `position + 1` only, and Spark raises on a type mismatch. The RePark card is F-IDLESS-TOPLEVEL-POSITIONAL-1. The top-level shapes of the remap ledger's S-20 and the top-level half of its S-26 are carried here.

**The ruling.** The owner ruled on 2026-11-01 that this residue blocks RePark's format-v2 label under section 1 of its order, and chartered this unit for the top level only. The nested half of the remap ledger's S-26 is a ruled divergence and stands.

**Spark measurements.** Spark 4.1.2 with Iceberg 1.11.0, copied from the orchestrator's notes and not re-measured by the clerk. The fork's answer before the fix is in brackets.

- `(a INT, b STRING)` over `(b STRING, a INT)` [`[(None, '1'), (None, '2')]`]: Spark raises.
- `(a INT, b BIGINT)` over `(b, a)` [`[(None, 1), (None, 2)]`]: Spark raises on `SELECT a, b` and reads `[(1,), (2,)]` on `SELECT b`.
- `(a INT, b DATE)` [a date read as an int]: Spark raises `ClassCastException`, per the card and the build brief (copied; the round-1 verdict does not list this shape). The earlier "not recorded" wording missed the card's answer (2026-11-02, the round-1 verdict's F5).
- `drop c`, then `add c` [the file's `c = 5` read]: Spark `[(1, None)]`.
- A mapping naming only `zz` over file `(a, c)` [`(1, 2)`]: Spark `(None, None)`.
- After `DROP COLUMN x` on table `(x, a, b)` over file `(a, b)`: Spark's projection is positional, and every filtered read returns zero rows. The fork answers coherently. This is a kept divergence (S-14).

**The fix, three files.** `field_id_stamping.rs` stamps a top-level file column `position + 1` always, and leaves unstamped a position whose id only a nested table field holds. `guarded_field_ids` gathers the projected, predicate and equality-delete key ids, and `refuse_positional_type_change` refuses a type or nesting-kind change on them. Round 4 (2026-11-02) replaced `guarded_field_ids` with `positional_guard`, which builds the read ids, the filter ids (predicate and equality-delete keys) and the file's physical types, and moved `type_promotion_is_valid` from `reader.rs` into `field_id_stamping.rs`. `reader.rs` passes the guarded ids in place of the projected ids. `record_batch_transformer.rs` `compare_schemas` compares field ids exactly, so a None against a Some is a difference, and an unmapped column reads NULL.
